All 8 C2 tests + 20 CBOM tests + ruff(scoped) + mypy GREEN. KEY GOTCHA: the aibom package ships INTENTIONALLY-LIGHT deps — `cryptography`/`pyOpenSSL` are NOT installed (they're only scan TARGETS in the fixture). So x509 parsing MUST be hand-rolled stdlib; do NOT `import cryptography` in product code. The DER reader extracts subject/issuer CN, self_signed (raw issuer-TLV == subject-TLV bytes), notBefore/notAfter (UTCTime YY>=50→19YY per RFC5280), signatureAlgorithm OID->name, and RSA modulus->keySize; parse_certificate() is TOTAL (returns None, never raises) so a malformed/non-cert file can't crash a scan. SPKI gotcha: the pubkey OID is nested INSIDE the AlgorithmIdentifier child of SubjectPublicKeyInfo, not a direct child. Cert props use crypto:notValidBefore/notValidAfter/subjectName/issuerName/selfSigned/signatureAlgorithm/publicKeyAlgorithm/keySize (mirrors CycloneDX certificateProperties for the C4 emitter). Related-crypto-material: scans RAW source text (NOT _strip_noncode) for inline PEM key blocks so the hardcoded PRIVATE KEY inside crypto_app.py's triple-quoted string IS caught; materialKind in CycloneDX relatedCryptoMaterialType enum (private-key/public-key/secret-key/initialization-vector/salt). IV/salt detection is deliberately NARROW (named-var = bytes/hex literal assignment only) so it yields 0 on the fixture (manifest has no IV/salt) and stays honest.
