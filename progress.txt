## C1 (BUILD) — landed 2026-06-30 — Python-AST crypto-API scanner + detection-rule model
- NEW `aibom/cbom/scanners/ast_crypto_scan.py` (`crypto_ast`, order=8): a true Python `ast`-based scanner
  with a data-driven rule corpus keyed by the RESOLVED CALL SYMBOL (last 1-2 dotted segments). The symbol
  fixes the primitive CONTEXT; the call ARGUMENTS supply the params. Buys 3 things the line-regex can't:
  (1) cross-statement constant-following (`RSA_BITS=3072` then `key_size=RSA_BITS` → RSA-3072 via a
  module/function const map + a small literal evaluator that folds `b"\x00"*16` / `a+b`);
  (2) nested-call binding (`Cipher(algorithms.AES(k), modes.CBC(iv))` → AES+CBC; `padding.OAEP` arg →
  scope-bound `crypto:padding`; PBKDF2 `iterations=` kwarg → `crypto:iterations`);
  (3) related-crypto-material from a LITERAL IV/nonce/salt bound to a mode/KDF call.
- LANE DISCIPLINE kept: scanner EMITs only (algorithm + related-material assets + rich props:
  crypto:detectedBy / detectionContext / detectionMethod=ast / confidence / padding / iterations). No
  scoring/flagging here (weak=C5/C6, PQC=C7, emit=C4).
- DEDUP DESIGN (the key gotcha): two scanners emitting the same component would DOUBLE the
  weak/pqc FLAG scanners (they iterate ctx.components mid-pipeline, BEFORE any pipeline dedup → 11 weak
  flags vs 6). Fix = the later regex scanner (order 10) DEFERS to AST-emitted refs via `ctx.has_ref(ref)`
  for both libs and algos, so it only adds usages AST can't see (e.g. tls_config.py's "AES" inside a
  cipher-suite STRING literal — AST can't read string literals; regex still catches it). Belt-and-suspenders:
  `pipeline._dedup_by_ref` collapses any same-ref dups to the richest (more properties) before building the
  ScanResult. DO NOT make the regex scanner "skip .py" — the oracle DEPENDS on regex finding the
  tls_config string-literal AES (test_strong_algorithms_in_the_fixture_are_not_flagged).

## C2 (BUILD) — landed 2026-06-30 — Java + Go crypto-API scanner (call-expression model)
- NEW `aibom/cbom/scanners/jvm_go_crypto_scan.py` (`crypto_jvm_go`, order=9, between AST=8 and
  regex=10). Python has a real `ast` module (C1); Java/Go DON'T (and vendoring a third-party grammar
  would break the no-OSS-tooling rule), so C2 is a clean-room **call-expression extractor**: strip
  comments (KEEP string literals — JCA transformation strings live in them), follow simple intra-file
  variable bindings, resolve algo+keysize+mode+curve+padding the SAME way C1 does. Same detection-rule
  model (symbol fixes the primitive CONTEXT, args supply params); only the per-language front-end differs.
- LIBRARY→ASSET maps implemented (R2 corpus): JCA/JCE (`Cipher/MessageDigest/Signature/Mac/KeyGenerator/
  KeyPairGenerator/SecretKeyFactory.getInstance`), BouncyCastle (engine classes + block-mode wrappers +
  digests + signers), Go stdlib `crypto/*` + `golang.org/x/crypto/{chacha20poly1305,bcrypt,argon2,scrypt,
  pbkdf2}`. Capabilities a flat regex can't: transformation split `AES/GCM/NoPadding`→algo+mode+padding;
  `SHA384withECDSA`→ECDSA signature; `KeyPairGenerator.getInstance("RSA")`+`kpg.initialize(2048)`→RSA-2048
  (cross-statement var bind); `new GCMBlockCipher(new AESEngine())`→AES-GCM (nested consume); Go
  `block:=aes.NewCipher` + `cipher.NewGCM(block)`→AES-GCM (block→mode var bind); `rsa.GenerateKey(rand,2048)`
  size; `ecdsa.GenerateKey(elliptic.P384())` curve.
- KEY GOTCHAS for C3 (JS/TS/C/Rust/.NET — same skeleton):
  1. Track EXPLICIT key size separately from the algo-table DEFAULT. `_display_name` only folds the
     explicit one (else 3DES→"3DES-168-CBC"). `_Asset` stores `explicit_size`; `resolved_size` (explicit
     or table default) is the `crypto:keySize` PROPERTY. Mirror the regex scanner's split exactly.
  2. Dedup is by (display-name, file). A cipher-RSA and a signature-RSA in the SAME file collapse to one
     "RSA" (first wins) — don't write a test that asserts a context that loses the dedup. (Fixed by making
     the Java signature ECDSA so it doesn't collide with the OAEP cipher-RSA.)
  3. Only attach a `crypto:mode` to a symmetric primitive — JCA's "RSA/ECB/OAEP..." has a bogus "ECB"
     field; gate on `algo_info(key).primitive in {block-cipher,stream-cipher,ae}`.
  4. Go reuses the var name `block` across functions → bind a mode wrapper to the NEAREST PRECEDING block
     of the same name by source position, not a dict (else GCM leaks onto the 3DES block).
  5. EMIT the same `crypto-algo-{slug(name)}-{slug(file)}` refs + run BEFORE the regex scanner so it
     defers via `ctx.has_ref`; reuse `_display_name/_refine_key/_slug` from algorithm_scan for ref parity.
     `crypto:detectionMethod="call-expr"` (vs C1's "ast"); per-language `crypto:detectedBy` library label.
