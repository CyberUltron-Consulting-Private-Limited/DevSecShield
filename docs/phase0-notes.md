# Phase 0 notes — reference tools & the clinical-imaging gap

*Spike for clinithread-aibom (the `aibom/` project). Sources: `docs/research-dossier.md`
§2 (head-to-head), §3 (standards), §5 (field/metadata table).*

## What we built in the spike
- A realistic clinical-imaging **test fixture** at `aibom/examples/clinical-imaging/`:
  `requirements.txt`, `config.json`, `MODEL_CARD.md`, `DATASET_CARD.md`, and a
  dummy `model.safetensors` — a chest X-ray triage SaMD repo.
- The committed golden BOM `expected/chestxr.cdx.json` is **generated by scanning
  that fixture** (`aibom emit -f cyclonedx examples/clinical-imaging`), not hand-written.

## How cisco-aibom and Trusera ai-bom structure their output

Both are Apache-2.0 Python generators and both emit the same primary formats, so
they are the right *approach* references (we mirror the approach, write our own code).

| | Cisco `cisco-aibom` | Trusera `ai-bom` |
|---|---|---|
| CycloneDX | **1.6 ML-BOM profile** | **1.6** |
| SPDX | **3.0 (AI + Dataset profiles)** | **3.0** |
| Other formats | SARIF 2.1, HTML, MD, CSV, JUnit, JSON, plaintext, live API (10 total) | SARIF 2.1, HTML dashboard, MD, CSV, JUnit (9 total) |
| Detection | LibCST (Python, deepest) + tree-sitter (JS/TS/Java/Go/Rust/Ruby/C#); 23 scanners, **30 component types**; mandatory agentic-LLM enrichment (`--llm-model`) | Regex (cross-language, fast); 13 **auto-registering** scanners; **0–100 risk score** + severity |
| Component model | rich taxonomy: models, agents, tools, MCP servers/clients, datasets, prompts, guardrails, secrets | Pydantic models; models, agents, APIs, datasets |
| Validation | policy engine (YAML gates); benchmark P/R/F1 | built-in JSON-Schema `--validate` |
| Compliance | EU AI Act / OWASP Agentic / NIST AI RMF (advisory) | EU AI Act / OWASP / licenses |

**CycloneDX shape both follow** (and we adopt): a model is a `component` of
`type: machine-learning-model` carrying a **`modelCard`** with `modelParameters`
(approach/task/architectureFamily/modelArchitecture/datasets/inputs/outputs),
`quantitativeAnalysis.performanceMetrics`, and `considerations` (users, useCases,
technicalLimitations, ethicalConsiderations, fairnessAssessments); plus
`pedigree.ancestors`, `externalReferences`, `licenses`, `hashes`; datasets as
`type: data`; libraries as `type: library` with `pkg:pypi/...` purls; and a
`dependencies[]` graph. Conventional filename `*.cdx.json`.

**Patterns we mirror:** Trusera's *auto-registering scanner* convention (adding a
scanner is one file) and its built-in **schema-validation gate**; Cisco's rich
*component taxonomy* and *modelCard* fidelity as the schema template. We do **not**
adopt Cisco's mandatory LLM enrichment (cost/keys) for the deterministic MVP.

## What neither tool has — the clinical-imaging fields we must ADD

Per dossier §5 (last rows) and §4 (use cases), neither generator is
healthcare-specific and neither produces FDA/EU-AI-Act readiness. The gaps we fill,
carried as **namespaced `properties[]`** (never invented top-level spec keys):

- **`clinical:`** — `intended_use`, `modality` (DICOM, e.g. DX/CT/MR), `body_part`,
  `pacs_ae_title` (PACS AE for the imaging orchestrator/DICOM routing).
- **`regulatory:`** — `fda_product_code`, `device_class` (e.g. II SaMD),
  `eu_ai_act_risk_tier` (high-risk / Annex I / MDR), and an advisory `disclaimer`.
- **`dataset:`** — `type`, `size`, `provenance`, `sensitivity` (PHI/de-identification),
  `known_bias` — the Datasheet/Dataset-Profile fields needed for GMLP traceability.

These map onto **SPDX 3.0 AI + Dataset profile** fields (energyConsumption,
useSensitivePersonalInformation, datasetType/sensitivity/biases) in Phase 2, and to
**FDA §524B / EU AI Act Annex IV / GMLP / HIPAA** requirements in Phase 3.

## Decisions / scope notes
- **CycloneDX 1.6 is primary** (broadest tool support, Ecma-424); SPDX 3.0 is Phase 2.
- **Offline schema validation is a hard gate** — schemas bundled under
  `src/aibom/schemas/`, no network at emit/validate time.
- **Determinism**: pinned timestamp + uuid5 serial from sorted bom-refs + file
  hashes ⇒ byte-stable golden output.
- Regulatory mapping is **advisory only** (CISA: "minimum elements create
  visibility, not assurance"); every BOM carries the disclaimer property.
- The full self-registering multi-language code scanner (LibCST/tree-sitter) lands
  with Phase 1+/2; Phase 1 covers a single Python model repo (manifest + config +
  cards + weight file).
