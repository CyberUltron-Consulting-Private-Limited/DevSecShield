Fixing A2 (canonical model node) + A3 (graph edges) clears "no model component", the 53 false-unlicensed (A4), and the broken supply-chain graph together. Sequence these early.

- "46 models" on chroma is catalog over-counting (provider supported-model lists), not real usage. A2 dedupe (used-vs-catalog) must bring it to the true count; the B1 benchmark oracles confirm truth.
- Compliance N/A is partly a bug (models not graph-wired) and partly correct (Chroma is not a clinical device; GMLP is out-of-scope, not fail). A9 introduces the tri-state.
- The PRODUCT ships NO runtime LLM (MVP): enrichment is deterministic (known-model KB + regex/AST), behind a provider interface so an LLM (Anthropic API or Bedrock) can be added later only if a customer requires it. Claude Code's OAuth login (the agent) is separate. Product ships no OSS BOM tool; oracles (Trusera/Cisco/CBOMkit) are bench/ only.
- CBOM = CycloneDX 1.6 crypto-asset (ECMA-424): 4 categories (algorithm/certificate/protocol/related-crypto-material) + nistQuantumSecurityLevel. Weak algos to flag: MD5, SHA-1, DES, 3DES, RC4, RSA<2048, ECB. PQC targets: ML-KEM/ML-DSA/SLH-DSA (FIPS 203/204/205); NIST deprecates RSA/ECC after 2030, disallows 2035.

Severity: ALL weak crypto -> "error" (SARIF error == High, per the secret scanner convention; SEVERITIES=("none","note","warning","error") — there is NO "high"/"critical" level). Flag codes: WEAK_ALGORITHM / WEAK_CIPHER_MODE / WEAK_KEY_SIZE / WEAK_PROTOCOL (frozenset WEAK_CRYPTO_CODES exported for C8/charts to read). CRITICAL GOTCHA: `crypto:strength=="weak"` is NOT the weakness test — the fixture's "DES" is detected as **3DES-CBC** with strength=**moderate** (3des is _MOD in rules.WEAK_ALGORITHMS), and AES-128-ECB is detected as **AES-ECB** with strength=**strong** (only the ECB mode is weak). So the predicate is multi-signal: (1) canonical-key ∈ rules.WEAK_ALGORITHMS [single source of truth — covers strength-weak AND moderate-but-deprecated 3DES/Blowfish], recovered via _base_key(name) which strips a trailing -GCM/-CBC/-ECB/... mode suffix then maps display→key through a reverse of ALGORITHM_NORMALIZE; (2) crypto:mode=="ECB" -> WEAK_CIPHER_MODE (catches strong cipher in ECB); (3) primitive in pke/signature/key-agree & keySize<2048 -> WEAK_KEY_SIZE (generic RSA/DSA/DH small key not in the table); (4) strength=="weak" fallback. One flag per component, precedence in that order. Fixture result: 5 weak algos {3DES-CBC,AES-ECB,MD5,RC4,RSA-1024} + 1 weak protocol TLS 1.0 = 6 weak flags; strong {RSA-2048,AES-GCM,AES,SHA-256} + cert + private-key material = 0 flags. mypy: component.properties is `dict|None` -> guard `props = component.properties or {}`. Adding flags does NOT break C4 emit (emitter reads no flags) nor leak into scan_repo (CBOM_SCANNERS only).
